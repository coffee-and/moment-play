# 게임 기록과 랭킹 계약

이 문서는 Moment Play의 게임별 로컬 기록과 공식 랭킹 기준을 한곳에 정리한다. 현재 동작의 최종 기준은 애플리케이션 코드와 `supabase/migrations`이며, 이 문서는 운영·기획·개발자가 그 계약을 빠르게 확인하기 위한 설명서다.

## 용어와 공통 원칙

- **로컬 기록**은 브라우저 `localStorage`에 저장되는 개인 기기 기록이다. 로그인하지 않아도 남지만 다른 브라우저나 기기로 동기화되지 않으며 사용자가 초기화할 수 있다.
- **공식 랭킹**은 로그인한 사용자의 서버 검증 결과만 Supabase에 저장하고 랭킹 화면에 노출한다.
- **연습 기록**은 힌트, 정답 공개, 되돌리기처럼 공정한 비교를 해치는 도움을 사용한 결과다. 게임을 끝낼 수는 있지만 공식 랭킹에는 제출하지 않는다. 게임에 따라 로컬 완료 횟수나 개인 기록은 남을 수 있다.
- 공식 랭킹은 서버가 발급한 시도, 보드, 규칙 버전, 도전 구간을 기준으로 한다. 클라이언트가 보낸 최종 점수나 시간은 신뢰하지 않고 입력 증거를 서버가 재생하거나 검증해 지표를 산출한다.
- 사용자마다 가장 좋은 결과 하나만 순위 계산에 사용한다. `rank_primary`, `rank_secondary`, `rank_tertiary`를 차례로 내림차순 비교하고 같은 지표 조합에는 같은 순위가 부여된다.
- 게임 규칙이나 점수 계산이 달라지면 기존 기록의 의미를 바꾸지 않고 `rulesVersion`을 올려 별도 계약으로 운영한다.
- 랭킹 테이블은 클라이언트가 직접 읽거나 쓰지 않는다. 기록 제출은 인증 사용자 전용 RPC, 조회는 제한된 리더보드 RPC를 사용한다.
- 최종 결과 요청은 사용자와 시도 ID에 묶인 복구 outbox에 먼저 기록한다. 화면을 이동해도 같은 제출을 계속하고, 일시적인 통신 실패나 응답 유실에는 동일 요청만 재전송하며 성공·영구 오류·보존 기한 만료 시 제거한다.

## 현재 운영 중인 공식 랭킹

모든 현재 보드는 `all-time`, 규칙 버전 `1`을 사용한다. 클라이언트 등록 정보는 `src/features/ranking/rankingRegistry.js`, 공용 서버 계약은 `supabase/migrations/20260820063057_generalize_ranked_game_results.sql`, Star Flight 검증 계약은 `supabase/migrations/20260820084728_add_ranked_star_flight_verification.sql`에 있다.

### 2048

- 보드: `2048 / classic`
- 표시 지표: `score`
- 순서: 점수가 높을수록 상위
- 로컬 기록: 게임 중 획득한 최고 점수
- 서버 검증: 서버가 발급한 시드로 보드를 다시 만들고 이동 입력을 순서대로 재생해 점수를 계산한다. 최초 랭킹 종료 시점 뒤에 추가 입력이 붙은 증거는 허용하지 않는다.

### Memory Sequence

- 보드: `memory / standard`
- 표시 지표: `score`
- 순서: 점수가 높을수록 상위
- 로컬 기록: 이번까지 완료한 가장 높은 라운드
- 공식 기록: 10라운드 코스에서 획득한 점수. 중도 게임 오버도 서버가 검증 가능한 입력 범위까지 계산한다.
- 서버 검증: 서버 시드로 각 라운드의 순서를 다시 만들고 선택 순서, 시간 초과, 생명과 재시도 게이지, 콤보 점수를 재생한다.

로컬의 `Best`는 도달 라운드이고 공식 랭킹 값은 점수이므로 서로 같은 수치가 아니다.

### Sudoku

- 보드: `sudoku / easy`, `sudoku / medium`, `sudoku / advanced`
- 표시 지표: `durationMs`
- 순서: 같은 난이도에서 완료 시간이 짧을수록 상위
- 로컬 기록: 전체와 난이도별 완료 횟수, 최단 시간, 마지막 완료 시각
- 서버 검증: 서버가 난이도에 맞는 퍼즐을 선택하고 입력 셀·숫자·경과 시각 이벤트를 검증한다. 최종 완료 시간은 서버가 관리하는 시도 시간에서 산출한다.
- 제외 조건: 힌트를 사용하거나 정답을 공개한 플레이는 공식 랭킹에 제출하지 않는다.

## Star Flight 랭킹 계약

Star Flight는 결정론적 20ms 고정 틱 시뮬레이션과 서버 시드 기반 재생을 사용한다. 공식 랭킹은 `flappy / course`, `flappy / endless` 두 보드로 분리되며 로컬 최고 기록과 별도로 저장된다.

### 코스 랭킹

- 코스 구성: 라운드당 90초, 총 5라운드
- 1차 기준: 코스 총점 높은 순
- 2차 기준: 최고 콤보 높은 순
- 3차 기준: 실수 횟수 적은 순
- 완주하지 못한 비행은 코스 랭킹에 제출하지 않는다.

### 무한 비행 랭킹

- 시작 난이도: 코스 5라운드 난이도
- 이후 진행: 생존하는 동안 난이도가 계속 상승
- 1차 기준: 생존 시간 긴 순
- 2차 기준: 점수 높은 순
- 3차 기준: 통과 게이트 많은 순

### 서버 검증 요구사항

- 서버가 시도 ID, 시드, 규칙 버전, 모드를 발급한다.
- 클라이언트는 점수 대신 플랩이 발생한 틱 목록을 제출하고 서버가 같은 고정 틱 시뮬레이션으로 결과를 재생한다.
- 틱 목록은 정렬·중복·범위·종료 뒤 입력·최대 크기를 검증한다.
- 일시정지나 백그라운드 전환이 발생한 플레이는 공식 기록 자격을 잃는다. 서버 경과 시간과 재생 시간이 허용 범위를 벗어나도 거부한다.
- 무한 비행은 최종 한 번에 무제한 입력을 제출하지 않고 검증 가능한 구간 단위 체크포인트로 나눈다.
- 클라이언트는 20초 단위로 체크포인트를 직렬 전송하며 서버는 구간당 최대 30초만 허용한다. 마지막 충돌 구간까지 서버가 `over`로 재생한 뒤에만 최종 결과를 확정한다.
- 새 랭킹 시도를 시작하면 결과가 없는 같은 보드의 이전 열린 시도와 체크포인트를 트랜잭션 안에서 제거하고 새 시도 ID를 발급한다. 이전 요청이 늦게 도착해도 존재하지 않는 시도 ID이므로 새 비행에 합쳐지지 않는다.

## 아직 공식 랭킹이 없는 게임

### Omok

현재 온라인 오목은 방, 참가자, 착수와 라운드 진행을 위한 기능이며 공식 전적이나 랭킹 기록이 아니다. 랭킹을 도입하려면 서버가 승패·기권·연결 종료를 최종 확정하고, 규칙과 상대 수준을 반영하는 레이팅 및 비정상 대국 처리 정책을 먼저 정해야 한다. 단순 누적 승수는 반복 대국과 상대 난이도 차이 때문에 공식 기준으로 사용하지 않는다.

### Timing Tap

10라운드의 합산 점수를 로컬 최고 기록으로 저장한다. 공식 랭킹을 도입할 때는 서버 발급 라운드 구성과 탭 시점을 검증하고 합산 점수를 서버에서 다시 계산해야 한다.

### Glow Sequence

완료한 가장 높은 라운드를 로컬 기록으로 저장한다. 기본 코스는 20라운드, Master는 60라운드까지 이어진다. 공식 랭킹은 두 코스를 분리하고, 서버 시드로 빛 순서를 재생한 뒤 완료 라운드와 실수 기준을 계산해야 한다.

### Solitaire

Easy는 한 장, Hard는 세 장씩 뽑으며 난이도별 완료 횟수와 최단 시간을 저장한다. 힌트나 되돌리기를 사용한 판은 최단 시간 갱신 대상에서 제외된다. 공식 랭킹은 검증된 딜 ID, 난이도, 이동 로그를 서버가 재생할 수 있을 때만 도입한다.

### LITS, Shikaku, Mosaic

각 게임은 정상 완주의 최단 시간을 로컬에 저장한다. 공용 퍼즐 세션 계약에 따라 힌트나 정답 공개를 사용하면 기록 자격을 잃는다. 현재 콘텐츠 수로는 같은 퍼즐 암기가 순위를 지배할 수 있으므로, 공식 랭킹 전에 충분한 검증 퍼즐과 퍼즐 ID·규칙 버전별 서버 검증 계약이 필요하다.

### Minesweeper

모든 안전한 칸을 연 최단 시간을 로컬에 저장하며 첫 선택 칸은 안전하게 생성한다. 힌트나 전체 정답 공개는 기록 자격을 잃는다. 공식 랭킹은 보드 크기와 지뢰 수별 보드를 분리하고 서버 시드, 첫 선택, 공개·깃발 입력을 재생해야 한다.

### SET

한 판에서 5개의 SET을 찾은 최단 시간을 로컬에 저장한다. 힌트나 정답 공개는 기록 자격을 잃는다. 공식 랭킹은 서버 시드로 카드 묶음과 교체 순서를 재현하고 선택한 세 장의 유효성을 검증해야 한다.

### Block Blast

더 놓을 수 있는 블록이 없어 종료될 때의 최고 점수를 로컬에 저장한다. 현재 힌트는 추천 배치를 보여 주므로 공식 랭킹 도입 시 도움 사용 여부를 분리해야 한다. 서버가 블록 공급 순서와 배치 입력을 재생하고 점수·줄 제거·콤보를 다시 계산할 수 있어야 한다.

## 구현 소유권

- 게임 목록과 경로: `src/features/minigames/data/minigameCatalog.js`
- 로컬 기록 키: `src/shared/storage/localStorageRegistry.js`
- 공식 랭킹 보드와 표시 형식: `src/features/ranking/rankingRegistry.js`
- 공용 제출 흐름과 복구 outbox: `src/features/ranking/useGameResultSubmission.js`, `src/features/ranking/rankedResultFinalizer.js`
- 서버 보드·시도·검증·조회 계약: `supabase/migrations/20260820063057_generalize_ranked_game_results.sql`, `supabase/migrations/20260820084728_add_ranked_star_flight_verification.sql`
- 만료된 미완료 시도 정리: `supabase/migrations/20260820164100_cleanup_expired_ranked_attempts.sql`
- DB 계약 검사: `supabase/tests/phase3_game_results_test.sql`

게임을 공식 랭킹에 추가할 때는 레지스트리만 늘리지 않는다. 서버 보드 등록, 시도 발급, 결정론적 검증기, 지표 산출, 클라이언트 제출, 랭킹 표시, 악성 증거 DB 계약 검사를 한 기능 단위로 함께 추가한다.

## 검증 방법

전체 DB 계약 실행 방법은 [Database contract tests](./database-contract-tests.md)를 따른다. 랭킹만 빠르게 확인하려면 격리된 로컬 Supabase를 실행한 뒤 다음 명령을 사용한다.

```sh
npm run test:db:ranking
```

`--linked`를 붙이거나 운영 프로젝트를 대상으로 실행하지 않는다. 테스트는 사용자와 결과 데이터를 만들기 때문에 반드시 로컬 격리 DB에서만 수행한다.

Supabase의 권한 모델은 테이블 접근 권한과 RLS가 서로 다른 계층이라는 점을 전제로 한다. 공개 스키마 테이블은 RLS와 최소 권한을 함께 유지하고, `SECURITY DEFINER` RPC는 호출 권한과 내부 사용자 검증을 별도로 점검한다.
