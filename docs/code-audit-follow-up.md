# Code audit follow-up

이 문서는 2026-08-17 전체 코드 재검사에서 확인한 후속 결함과 구조 개선 항목을 기록한다. 이전 감사의 완료 기록은 `docs/code-audit-remediation.md`에 유지하며, 이번 문서는 해당 작업 이후에도 남아 있거나 새로 확인된 문제만 다룬다.

## 작업 원칙

- 증상을 숨기는 조건문, 후행 CSS 덮어쓰기, 임의의 예외 선택자를 추가하지 않는다.
- 상태와 스타일의 실제 소유권을 바로잡고 교체된 코드와 미사용 규칙을 함께 제거한다.
- 전역 토큰과 기본값은 `src/shared/styles/foundation.css`가 소유한다.
- 기능별 스타일은 CSS Modules를 기본으로 하고 공용 UI의 의미 기반 계약을 사용한다.
- 서버가 신뢰해야 하는 결과는 클라이언트 값이나 UI 흐름에 의존하지 않는다.
- 각 작업은 독립적으로 검증하고 다른 항목의 변경을 섞지 않는다.
- 테스트는 문구 위치나 내부 DOM 순서가 아니라 상태 전이, 신뢰 경계, 접근성 계약과 회귀 조건을 검증한다.

## 1. Timing Tap 종료 확인 상태 결함

- 애니메이션은 `phase === "playing"`만 검사하고 종료 모달 상태를 알지 못한다.
- 종료 요청은 게임 단계를 정지하지 않고 `isExitOpen`만 변경한다.
- 전역 Space/Enter 핸들러가 버튼·입력 요소를 제외하지 않아 모달 조작이 뒤쪽 게임의 `tapNow()`로 전달될 수 있다.
- 전역 핸들러의 `preventDefault()`가 모달 버튼의 키보드 활성화도 막을 수 있다.
- TAP 버튼은 포인터 이벤트만 직접 처리하므로 보조기기가 발생시키는 합성 클릭 계약이 없다.
- 현재 테스트는 `timingTap.logic.js`의 순수 로직만 다루고 이 컴포넌트 상태 결합을 검증하지 않는다.

### 1번 완료 기록

- 종료 확인 상태를 Timing Tap 실행 여부와 연결해 모달이 열리면 바늘 프레임과 판정 후 라운드 전환 타이머를 즉시 정지하도록 했다.
- 바늘의 누적 경과 시간과 판정 피드백의 남은 시간을 각각 보존하고, 계속하기 또는 Escape로 닫을 때 모달 체류 시간을 제외한 지점부터 재개한다.
- 공용 `GameStage`에 의미 기반 `isPaused` 계약을 추가해 일시정지 중 게임 콘텐츠의 CSS 애니메이션도 멈추도록 했다.
- 전역 Space·Enter 입력은 모달과 다른 대화형 요소에서 무시하고, TAP은 네이티브 `click` 계약으로 처리해 키보드와 보조기기 활성화를 동일한 경로로 통합했다.
- 계속하기를 초기 포커스로 지정했으며 ESLint, Stylelint, 61개 파일의 Vitest 318개와 프로덕션 빌드를 통과했다. 새 테스트는 추가하지 않았다.

## 2. Sudoku 랭킹 신뢰 경계 결함

- 클라이언트 퍼즐 데이터에 세 난이도의 완성 답안이 포함되어 있다.
- 세 퍼즐은 서로 다른 초기 보드를 사용하지만 완성 답안은 동일하다.
- 서버 검증은 제출 보드와 저장된 답안의 일치 여부만 확인한다.
- 서버 경과 시간의 하한이 1,000ms라 인증 사용자가 공개된 답을 바로 제출해 비정상적으로 짧은 기록을 만들 수 있다.
- 답안을 난독화하거나 파일 위치를 옮기는 방식은 보안 경계를 만들지 못한다. 랭킹용 발급·증명·시간 검증을 서버 기준으로 다시 설계해야 한다.

### 2번 완료 기록

- 랭킹 퍼즐 선택권을 클라이언트에서 제거하고 `begin_ranked_game`이 요청한 난이도 안에서 서버 전용 퍼즐을 무작위로 발급하도록 변경했다. 발급 응답에는 플레이 보드와 proof 버전만 포함되며 정답은 `private` 스키마에 유지한다.
- 브라우저 번들의 정답 배열을 제거하고 입문·중급·도전 퍼즐을 각각 42·34·27개의 단서를 가진 유일해 보드로 교체했다. 로컬 연습의 힌트와 포기 화면은 실행 시 계산한 해답을 사용하지만 이 값은 랭킹 검증에서 신뢰하지 않는다.
- 랭킹 proof를 최종 보드 제출에서 셀 입력 이벤트 스트림으로 교체했다. 서버는 발급된 초기 보드에서 이벤트를 순서대로 재생하면서 고정 단서 수정, 잘못된 필드·값, 역행하는 시간, 과도한 이벤트와 미완성 결과를 거부한다.
- 난이도별 최소 플레이 시간과 최대 시도 시간을 서버 정책으로 두고, 최종 기록은 클라이언트 타임스탬프가 아니라 서버의 시도 시작 시각으로 계산한다. 이전 `board` 제출 계약과 즉시 생성한 완성 이벤트 제출은 모두 거부한다.
- 랭킹 DB 계약 테스트를 82개로 확장해 서버 발급, 비공개 정답, 호출자 퍼즐 지정 차단, 악성 이벤트, 서버 시간, 정상 완료와 중복 제출 수명주기를 실제 RPC로 검증했다.

## 3. 2048 랭킹 종료 조건 결함

- 서버 검증기는 proof의 모든 이동을 끝까지 재생한다.
- 재생이 끝난 마지막 보드만 검사해 2048 이상 도달 또는 이동 불가 상태를 랭킹 종료로 인정한다.
- 정상 UI는 최초 2048 도달 시 제출하지만 직접 RPC를 호출하면 도달 이후의 유효 이동을 추가해 점수를 부풀릴 수 있다.
- 최초 랭킹 종료 조건을 만난 시점에서 검증을 끝내고 남은 이동이 있으면 proof 전체를 거부해야 한다.

### 3번 완료 기록

- 2048 도달과 이동 불가를 함께 판정하는 `private.ranked_2048_is_terminal`을 서버의 단일 종료 규칙으로 만들고 브라우저 역할의 직접 실행 권한을 회수했다.
- 서버 재생기는 각 이동 전에 이미 종료 상태인지 확인한다. 최초 종료 뒤 이벤트가 하나라도 남아 있으면 이후 이동의 유효성이나 최종 보드와 관계없이 proof 전체를 거부한다.
- proof의 허용 필드를 `moves` 하나로 제한해 클라이언트가 점수나 별도 상태를 함께 전달하는 느슨한 계약도 제거했다.
- 고정 시드에서 정확히 2048에 도달하는 정상 950개 이동은 20,256점으로 승인하고, 그 뒤 실제 추가 점수를 만들 수 있는 두 이동을 붙인 proof는 거부하는 RPC 수명주기 테스트를 추가했다. 이동 불가로 끝나는 별도 replay도 종료 직후까지만 승인하도록 검증했다.
- 수명주기 테스트 중 2048·Memory의 공용 시드 생성기가 제한된 함수 `search_path` 밖의 `extensions` 스키마를 참조해 랭킹 시작이 실패하는 기존 결함을 발견했다. `search_path`를 넓히지 않고 `extensions.gen_random_bytes`로 명시해 함께 복구했다.
- 랭킹 DB 계약 테스트 97개에서 시작 응답, 두 종료 유형, 후행 이동 거부, 정상 점수 저장과 중복 제출을 통과했다.

## 4. CSS 토큰 결함

- `logic-puzzle-stage.css`가 foundation에 없는 `--palette-neutral-200`과 `--shadow-soft`를 사용한다.
- fallback이 없어 해당 `background`와 `box-shadow` 선언 전체가 브라우저에서 무효화된다.
- 현재 Stylelint는 선언 중복과 잘못된 속성은 검사하지만 사용자 정의 속성의 정의 존재 여부는 확인하지 않는다.
- 기존 의미 기반 표면·그림자 토큰 중 실제 디자인 역할에 맞는 토큰으로 교체하고 정적 검증 범위를 보완해야 한다.

### 4번 완료 기록

- 공용 퍼즐 답안 요약과 힌트 패널이 존재하지 않는 원시 팔레트·그림자 이름을 참조하던 규칙을 제거하고 실제 역할이 같은 `--stage-card-surface`, `--stage-card-border`, `--stage-card-shadow` 계약으로 통일했다.
- `scripts/check-css-custom-properties.mjs`를 추가해 전체 CSS 정의, CSS의 `var(...)` 사용, JSX·JavaScript의 런타임 사용자 정의 속성 주입과 `var(...)` 사용을 하나의 정의 그래프로 검사한다.
- 명시적 fallback이 없는 사용자 정의 속성이 CSS나 런타임에서 정의되지 않았으면 파일과 줄 번호를 출력하고 실패하도록 했다. 컴포넌트 입력처럼 fallback을 가진 선택적 속성은 유효한 계약으로 유지한다.
- 새 검사를 기존 `npm run quality`에 연결했다. 교체 전에는 누락 세 위치를 정확히 검출했고, 교체 후에는 35개 CSS 파일과 전체 런타임 소스에서 304개 사용자 정의 속성 정의의 정합성을 통과했다.

## 5. DB 테스트와 CI 결함

- `package.json`에 네 종류의 DB 테스트 스크립트가 있지만 App CI와 Pages 배포에서는 실행하지 않는다.
- 현재 랭킹 pgTAP은 `begin_ranked_game`, `complete_ranked_game`의 존재·권한은 확인하지만 실제 RPC 수명주기와 악성 proof를 호출하지 않는다.
- 이 때문에 Sudoku와 2048 검증 결함이 DB 테스트를 모두 통과한다.
- 운영 DB에 테스트를 직접 실행하지 않고 로컬 Supabase, 임시 브랜치 또는 격리된 통합 DB에 마이그레이션을 적용한 뒤 pgTAP을 실행해야 한다.

### 5번 완료 기록

- Supabase CLI를 정확한 버전의 개발 의존성으로 고정하고 `supabase/config.toml`을 추가해 새 환경에서도 동일한 PostgreSQL 17 로컬 DB를 재현하도록 했다.
- 모든 DB 테스트 스크립트를 로컬 `supabase test db` 계약으로 통합해 기존 `--linked` 원격 실행 경로를 제거했다. 전체 스위트와 랭킹·친구·초대·인증별 집중 실행 명령을 동일한 진입점 위에 유지한다.
- App CI를 재사용 가능한 품질 게이트로 만들고 별도 DB 작업에서 로컬 DB 시작, 전체 마이그레이션 적용, pgTAP 실행, 정리를 수행하도록 했다.
- Pages 배포는 같은 App CI를 호출하고 성공 결과에 의존한다. 기존에 배포 워크플로 안에서 중복 실행하던 정적 검사와 애플리케이션 테스트는 제거했다.
- 랭킹 pgTAP에는 앞선 2·3번 작업에서 정상 Sudoku·2048 완료와 조작·과잉 proof 거부 수명주기가 포함되어 있다. 로컬 환경에는 Docker 런타임이 없어 컨테이너 실행은 CI 검증 대상으로 남기고, CLI 명령·설정·애플리케이션 품질 게이트는 로컬에서 검증했다.

## 6. Supabase Auth 설정

- 실서비스 Security Advisor에서 `Leaked Password Protection Disabled` 경고를 확인했다.
- 비밀번호 인증을 제공하므로 유출 비밀번호 검사를 활성화하고 인증 정책과 사용자 안내를 함께 확인해야 한다.
- `SECURITY DEFINER` 실행 경고는 대부분 의도한 RPC 표면이다. 명시적 역할 권한, `auth.uid()` 소유권 검사, 고정 검색 경로가 유지되는지 작업 후 다시 확인한다.
- 정책이 없는 랭킹 내부 테이블과 `game_results`는 직접 테이블 권한을 회수하고 RPC만 허용하는 현재 설계가 의도된 상태다.

## 10. 미사용 파일·코드·계약 정리

프로덕션 진입점 `src/main.jsx`에서 정적 import, 동적 import, CSS import와 에셋 URL을 따라 전체 그래프를 확인했다. 이름이 비슷하거나 참조 횟수가 적다는 이유만으로 삭제하지 않고 실제 코드·테스트·문서·DB 계약 소비자를 다시 검색했다.

### 즉시 삭제 가능한 파일과 에셋

- `src/shared/components/editorial/EditorialLabel.jsx`는 GameStage 구조 교체 때 마지막 소비자가 제거됐다. 현재 파일 외 참조가 없으며 파일을 삭제하면 비는 `editorial` 디렉터리도 함께 제거할 수 있다.
- Flappy의 `fin-whale-blue.svg`, `fish-blue.svg`, `fish-yellow.svg`, `whale-blue.svg`, `wing-blue.svg`, `wing-yellow.svg` 여섯 파일은 현재 인라인 `FlappyFish` SVG로 교체된 이전 구현 에셋이다. import 그래프와 빌드 산출물 어디에도 포함되지 않는다.
- `dist/`는 Git에서 제외된 생성물이라 로컬에서는 언제든 삭제 후 `npm run build`로 재생성할 수 있다. 저장소 정리 커밋에는 포함하지 않는다.

### 즉시 삭제 가능한 JavaScript 잔재

- `getLongestLine`, `getFallbackOnlineNickname`, `getOnlineRoleForStone`, `getBoxIndex`는 선언 외 소비자가 없다.
- `gameProgression.js`의 endless 난이도 상수와 `normalizeEndlessDifficulty`, `getEndlessRoundProgress`, `getNextEndlessDifficulty`, `canAdvanceEndlessDifficulty`, `formatEndlessMilestone`는 실제 게임에서 사용되지 않고 해당 함수 자체를 검사하는 테스트에서만 사용된다.
- `touchRetainedData`는 실제 저장 흐름에서 호출되지 않고 전용 테스트만 남아 있다.
- `getSupabaseConfigStatus`는 앱에서 사용되지 않고 테스트 전용 진단 객체만 반환한다. 운영 코드는 `isSupabaseConfigured`만 사용한다.
- `LITS_SOLUTION`은 `LITS_PUZZLES[0].solution`의 테스트용 별칭일 뿐이며 게임은 해당 별칭을 사용하지 않는다.
- 미니게임 카탈로그의 모든 `recordType`, `rankingType` 속성은 어떤 화면·저장·랭킹 로직에서도 읽히지 않는 사장된 메타데이터다.
- 위 테스트 전용 코드의 테스트는 기능 회귀를 보장하지 않으므로 구현과 함께 제거하거나 실제 소비자 계약을 검증하도록 바꾼다.

### 4번 완료 기록

- 전역 `InviteNotificationProvider`와 친구 화면 훅이 동일한 초대 RPC, 요청 중복 제거, 주기 타이머, 포커스·가시성 이벤트를 각각 소유하던 구조를 제거했다. 친구 화면에 들어가면 두 폴링 주기와 두 스냅샷이 경쟁하던 것이 원인이었다.
- Provider가 사용자 ID가 결합된 전체 초대 스냅샷을 단일 원본으로 소유하고, 배지 수와 최근 처리 결과는 그 배열에서 파생한다. 사용자 전환 시 이전 사용자의 스냅샷은 effect 정리를 기다리지 않고 즉시 소비자에게서 격리된다.
- 최초 조회, 수동 새로고침, 초대 생성·수락·거절·취소 뒤 갱신, interval·focus·visibility 갱신은 모두 Provider의 하나의 요청 계약을 사용한다. 친구 화면 훅은 초대 데이터를 따로 저장하거나 폴링하지 않고 공용 스냅샷을 표시하며 오류 노출만 담당한다.
- Supabase 조회에 `AbortSignal`을 전달하고 사용자 전환·Provider 언마운트에서 진행 중 요청을 취소한다. 같은 사용자의 동시 갱신은 한 요청으로 합치고, 취소되거나 이전 사용자가 시작한 응답은 상태를 변경하지 않는다.
- Provider 스냅샷 노출·동시 요청 병합·요청 취소·계정 간 데이터 격리와 친구 화면의 단일 초대 조회를 회귀 검사로 고정했다. ESLint, Stylelint, CSS 토큰 검사, Vitest 62개 파일 328개, Playwright 5개와 301개 모듈 프로덕션 빌드를 통과했다.
