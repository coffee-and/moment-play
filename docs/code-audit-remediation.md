# Code audit remediation

이 문서는 2026-08-16 전체 코드 감사에서 확인한 결함과 구조 개선 작업의 실행 순서를 고정한다. 각 항목은 독립된 커밋 하나로 완료하고, 검증이 끝난 뒤 상태와 커밋을 갱신한다.

| 순서 | 상태 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 완료 | 랭킹 결과의 클라이언트 신뢰 제거 | 서버가 발급한 시도만 완료할 수 있고, 서버가 게임 증명을 재검증해 산출한 결과만 랭킹에 노출된다. |
| 2 | 완료 | Supabase `SECURITY DEFINER` 실행 권한 최소화 | 의도한 RPC 외 함수의 `PUBLIC`/`anon` 실행 권한을 회수하고 Advisor 결과를 재확인한다. |
| 3 | 완료 | 취약 의존성 업데이트 | React Router와 전이 의존성 취약점을 제거하고 전체 검증을 통과한다. |
| 4 | 완료 | 게임 경로 변경 시 시작 게이트 우회 제거 | 현재 경로와 시작 승인을 동기적으로 결합해 새 게임의 선행 마운트를 막는다. |
| 5 | 완료 | 로컬 저장 키와 초기화 책임 통합 | 모든 게임 기록 키를 중앙 관리하고 초기화 누락을 제거한다. |
| 6 | 완료 | 게임 액션 피드백 CSS 중복 제거 | 기본·효과·배치 스타일의 소유권을 분리하고 import 순서 의존과 중복 keyframes를 없앤다. |
| 7 | 완료 | GameStage 전역/공용 셸 스타일 통합 | 무효화된 전역 선언을 제거하고 GameStage 스타일의 단일 소유권을 확립한다. |
| 8 | 완료 | 게임별 코드 분할 | 게임 컴포넌트를 지연 로딩해 초기 번들 경고와 불필요한 다운로드를 제거한다. |
| 9 | 완료 | 대형 게임·친구 모듈 책임 분리 | 상태 전이, 네트워크, 저장, 화면 렌더링 책임을 명시적 모듈로 분리한다. |
| 10 | 완료 | 앱/게임 Error Boundary 도입 | 화면 전체 백지화를 막고 복구 가능한 오류 화면을 제공한다. |
| 11 | 대기 | 공용 모달 포커스·스크롤 관리 정리 | 포커스 트랩, 배경 inert, 중첩 스크롤 잠금을 공용 관리자에서 처리한다. |
| 12 | 대기 | 정적 품질 게이트 도입 | ESLint, React Hooks, 접근성, Stylelint, 타입/정적 검사를 CI에 추가한다. |
| 13 | 대기 | Supabase 성능 Advisor 항목 정리 | 누락 FK 인덱스와 RLS initplan을 정리하고 미사용 인덱스를 사용 근거에 따라 결정한다. |

## 작업 원칙

- 증상을 가리는 선택자 추가나 임의 범위 제한 대신 원인이 된 책임과 신뢰 경계를 수정한다.
- 항목 사이의 변경을 섞지 않는다.
- 기존 테스트를 실행하고 필요한 경우 기존 테스트를 새 계약에 맞게 갱신하되, 별도 테스트 파일은 추가하지 않는다.
- 데이터베이스 변경은 마이그레이션으로 남기고 직접 테이블 쓰기보다 최소 권한 RPC를 사용한다.

## 1번 완료 기록

- 브라우저의 `game_results` 직접 INSERT 경로와 권한, RLS INSERT 정책을 제거했다.
- `begin_ranked_game`이 영구 계정에 일회성 시도를 발급하고, `complete_ranked_game`이 해당 사용자·시도·제출 ID를 잠금 상태에서 검증한다.
- 2048은 서버 시드로 보드를 재생해 점수를 산출하고, 메모리는 서버 시드와 라운드 입력 이력으로 상태·점수·최소 소요 시간을 재생한다.
- 스도쿠는 서버가 발급한 퍼즐과 제출 보드를 대조하고 서버 시각으로 소요 시간을 산출한다.
- 검증 시각이 있는 결과만 리더보드에 노출하며, 기존 클라이언트 신뢰 기록은 랭킹에서 제외한다. 기존 서버 전용 오목 기록은 유지한다.
- 별도 테스트 파일은 추가하지 않고 기존 프런트 테스트와 DB 계약 테스트를 새 흐름에 맞게 갱신했다.

## 2번 완료 기록

- PostgreSQL 함수의 기본 `PUBLIC EXECUTE`를 만든 함수마다 사후 회수하는 대신, `postgres` 소유자가 앞으로 `public` 스키마에 만드는 함수까지 기본 거부하도록 변경했다.
- 현재 `postgres` 소유 `public` 함수의 `PUBLIC`·`anon`·`authenticated` 실행 권한을 먼저 전부 회수한 뒤, 실제 클라이언트 RPC 26개와 RLS 평가용 함수 1개만 `authenticated`에 다시 허용했다.
- 로그인 전 공개가 제품 요구사항인 리더보드 RPC 하나만 `anon`에 허용했다.
- Auth 사용자 생성·활동 갱신·보존 정리 트리거와 플랫폼 `rls_auto_enable` 함수는 브라우저 역할이 직접 실행할 수 없게 했다.
- 적용 전 Security Advisor 기준 11개의 익명 `SECURITY DEFINER` 경고 중 10개가 제거 대상이며, 공개 리더보드 1개만 의도된 예외다. 인증 역할 경고는 명시적 RPC/RLS 허용 목록만 남긴다.
- 별도 테스트 파일 없이 기존 사전 출시 DB 테스트에 전역 함수 권한 행렬과 기본 권한 회귀 검사를 추가했다.

## 3번 완료 기록

- 직접 의존성인 `react-router-dom`을 보안 수정이 포함된 7.18.2로 올리고 함께 설치되는 `react-router`도 7.18.2로 갱신했다.
- Vite와 jsdom의 기존 버전 범위 안에서 전이 의존성 `nanoid` 3.3.18, `postcss` 8.5.26, `undici` 7.29.0을 잠금 파일에 반영했다.
- 강제 `overrides`나 불필요한 메이저 업그레이드 없이 의존성 트리를 정상 해석했으며 `npm audit` 취약점 0건을 확인했다.
- 별도 테스트 파일은 추가하지 않았고 기존 프런트 테스트 325개와 프로덕션 빌드를 통과했다.

## 4번 완료 기록

- 경로와 무관한 `hasStarted`를 렌더 후 `useEffect`로 초기화하던 구조를 제거했다. 이 구조에서는 같은 라우트 컴포넌트가 재사용될 때 새 게임이 한 번 마운트된 뒤에야 시작 화면으로 돌아갔다.
- 게임 시작 상태를 `location.pathname`으로 식별되는 `MinigameRouteSession` 안으로 옮겼다. 게임 또는 온라인 대기실 경로가 바뀌면 React가 새 세션을 동기적으로 생성하므로 이전 경로의 시작 승인이 전달되지 않는다.
- 타이머, 지연 렌더링, 게임별 예외 조건 없이 공용 게임 페이지의 상태 소유권을 바로잡아 모든 게임 경로에 같은 규칙을 적용했다.
- 별도 테스트 파일은 추가하지 않고 기존 게임 페이지 테스트에 선행 마운트 회귀 조건을 반영했으며, 전체 프런트 테스트 326개와 프로덕션 빌드를 통과했다.

## 5번 완료 기록

- 각 게임과 공용 모듈에 흩어져 있던 13개 게임 기록 키, 테마·로컬 프로필 키, 사용자별 초대 결과 접두사를 `localStorageRegistry`의 단일 출처로 통합했다.
- 기존 저장 키 값은 그대로 유지해 사용자 기록을 잃지 않도록 했으며 모든 게임은 레지스트리의 키를 참조한다.
- 초기화 함수는 등록된 플레이 데이터 키를 명시적으로 제거하면서 기존 `eunContents.` 레거시 데이터도 함께 정리한다. 따라서 다른 접두사를 사용해 누락되던 솔리테어 기록도 삭제되고 테마와 무관한 외부 데이터는 보존된다.
- 별도 테스트 파일 없이 기존 초기화 테스트를 전체 등록 키 기준으로 갱신했으며, 전체 프런트 테스트 326개와 프로덕션 빌드를 통과했다.

## 6번 완료 기록

- 전역 토큰·테마·기본 요소 규칙을 `src/shared/styles/foundation.css`로 실제 이동하고 앱 스타일보다 먼저 불러오도록 진입점을 정리했다. 기존 `styles.css`에는 앱 레이아웃과 화면 스타일만 남겼다.
- 세 전역 파일과 Flappy 파일에 중복되어 있던 액션 피드백의 기본 규칙·효과·배치·동일 keyframes를 제거하고, `GameActionFeedback.module.css`가 공용 컴포넌트 내부 표현을 단독 소유하도록 통합했다.
- Set, Block Blast, Timing Tap, Flappy의 위치·보드 효과·게임 팔레트는 각 기능의 CSS Module로 옮겼다. 공용 컴포넌트에는 게임 이름이나 게임별 선택자를 남기지 않고, 명시적인 `className`과 CSS 사용자 속성 계약으로 연결했다.
- 공용 피드백 파일에 섞여 있던 Memory 성공 표시 규칙은 Memory 스타일로 되돌렸고, 소비자가 없는 Flappy 꼬리·지느러미 덮어쓰기 규칙은 제거했다.
- 새 스타일에는 `!important`나 끝단 덮어쓰기 규칙을 추가하지 않았고, 기존 테스트 파일만 모듈 경계에 맞게 갱신했다. 전체 프런트 테스트 326개와 프로덕션 빌드를 통과했다.

## 7번 완료 기록

- 이전 2열 카드 셸을 렌더링한 뒤 별도 전역 파일이 높은 구체성으로 숨기고 다시 배치하던 구조를 제거했다. 사용되지 않던 제목·설명·장식 마크업과 빈 사이드바도 함께 삭제했다.
- `GameStage`와 오버레이·모달의 레이아웃, 반응형 규칙, 터치 피드백을 `GameStage.module.css` 한 곳이 소유하도록 통합했다. 게임별 스타일은 `data-stage-slot` 공개 계약만 사용하므로 내부 클래스명이나 전역 import 순서에 의존하지 않는다.
- 헤더와 게임 스테이지의 원형 아이콘 버튼을 공용 `IconButton` 계약으로 통합했다. 소리 아이콘 상태 전환은 유지하면서 크기·표면·포커스·비활성·모션 규칙은 의미 기반 토큰과 실제 디자인 차이를 나타내는 variant로 관리한다.
- 게임 가이드 확인 버튼은 공용 `Button`을 사용하고, 스테이지 버튼과 입력은 공용 컴포넌트가 소비하는 의미 기반 CSS 변수로 스타일을 주입하도록 정리했다. 전역 토큰과 기본값은 `foundation.css`에만 추가했다.
- 앱 셸과 게임 피드백·모달의 쌓임 순서를 제한된 전역 레이어 토큰으로 교체했다. Solitaire 카드 스택은 덱 크기에서 계산되는 로컬 레이어 계약과 자연스러운 선택자 순서로 수정해 저장소의 `!important`를 모두 제거했다.
- 교체된 셸 CSS 2개와 오디오 버튼 CSS, 더 이상 소비되지 않는 전역 선언을 삭제했다. 별도 테스트 파일은 추가하지 않고 기존 선택자 테스트만 새 공개 계약에 맞게 갱신했으며, 전체 프런트 테스트 326개와 프로덕션 빌드를 통과했다.

## 8번 완료 기록

- 14개 게임 컴포넌트를 한 레지스트리에서 정적으로 import하던 구조를 명시적 동적 import 레지스트리로 교체했다. 각 게임은 독립된 JS·CSS 청크로 생성되며 홈과 게임 목록을 보는 동안에는 다운로드되지 않는다.
- 게임 지원 여부 조회와 실제 지연 컴포넌트 조회를 분리했다. 카드 UI는 모듈 로더를 건드리지 않고 지원 여부만 확인하고, 게임 컴포넌트는 인증과 명시적 시작 승인이 끝난 뒤 처음 렌더링된다.
- named export를 안전하게 React 지연 컴포넌트로 변환하는 `lazyNamedComponent`를 공용 계약으로 만들었다. 게임 레지스트리와 앱 라우트가 같은 검증·변환 로직을 사용하므로 개별 `.then()` 변환이나 기본 export 강제 변경이 없다.
- 게임만 분리한 중간 빌드에서 초기 JS가 756.37kB에서 544.66kB로 줄었지만 경고 기준을 넘는 것을 확인했다. 원인이던 비활성 기능 페이지의 정적 라우트 import도 자연스러운 라우트 경계로 분리하고, 홈은 초기 화면으로 유지했다.
- 게임 시작과 기능 라우트에 각각 접근 가능한 `Suspense` 로딩 화면을 두었다. 수동 `manualChunks`, 임의 청크명, 경고 기준 상향, 의도하지 않은 사전 로딩은 사용하지 않았다.
- 최종 초기 JS는 468.85kB로 줄어 500kB 초과 경고가 제거됐고, 게임별 JS는 4.42~45.12kB 범위의 독립 청크로 생성됐다. 별도 테스트 파일은 추가하지 않았으며 전체 프런트 테스트 326개와 프로덕션 빌드를 통과했다.

## 9번 완료 기록

- 파일 크기만 기준으로 나누지 않고 실제 책임 결합을 다시 감사했다. 오목은 이미 로컬 상태 훅과 온라인 룸 훅이 존재해 유지하고, Supabase 호출·폴링·검색·초대 상태·화면을 함께 소유한 `FriendsPage`와 타이머 상태 머신·기록 저장·랭킹 제출·대형 화면을 함께 소유한 `MemoryOrderGame`을 정리 대상으로 확정했다.
- 친구 기능의 서버 호출, 대시보드 갱신, 중복 초대 새로고침 방지, 포커스·가시성 폴링, 검색·관계·초대 액션 상태를 `useFriendsDashboard`로 이동했다. `FriendsPage`는 인증 분기와 화면 조합만 담당하며 인프라 게이트웨이를 직접 알지 않는다.
- 친구 코드 정규화, 서버 오류 번역, 관계 라벨, 친구·초대 그룹화는 순수 `friendsPageModel`로 분리했다. 초기 대시보드 요청은 언마운트 후 상태를 갱신하지 않으며 복사 상태 타이머도 훅 해제 시 정리한다.
- 메모리 게임의 단계·타이밍·기호 설정은 `memoryGameConfig`, 로컬 최고 기록 접근은 `memoryBestRecord`가 단독 소유한다. 기존 저장 키와 외부 테스트용 export 계약은 그대로 유지했다.
- 메모리 보드와 입력 렌더링은 `MemoryGameBoard`, 시작·전환·결과 모달은 `MemoryGameOverlays`로 분리했다. `MemoryOrderGame`은 기존 검증된 상태 전이와 랭킹 제출을 오케스트레이션하고 각 뷰에는 명시적인 상태와 명령만 전달한다.
- 새 테스트 파일은 추가하지 않았고 기존 친구·메모리 테스트를 포함한 전체 프런트 테스트 326개와 프로덕션 빌드를 통과했다. 초기 번들은 468.85kB를 유지하며 빌드 경고가 없다.

## 10번 완료 기록

- React 클래스 기반 `ErrorBoundary`를 공용 오류 포착 계약으로 추가했다. 공용 계층은 오류 상태·경로 변경 시 초기화·선택적 보고 훅만 소유하며 앱이나 게임 문구를 알지 않는다.
- 앱 Provider 전체, 일반 기능 라우트, 인증과 명시적 시작 승인을 통과한 활성 게임에 각각 독립된 경계를 배치했다. 기능 오류는 일반 화면의 헤더·푸터를 유지하고, 게임 오류는 해당 게임 영역에서만 차단되며, Provider 오류는 최상위 복구 화면으로 수렴한다.
- 공용 `ErrorFallback`은 기존 `StatusPanel`·`Button`과 의미 기반 토큰을 재사용한다. 중앙 배치·안전 영역·반응형 액션 배치만 CSS Module이 소유하며 전역 덮어쓰기, 원시 색상·그림자·반지름, `!important`를 추가하지 않았다.
- 지연 로딩 청크 오류는 React의 캐시된 실패 상태를 단순 재렌더링하지 않고 문서 재로딩으로 복구한다. 일반 화면에는 홈 이동, 게임 화면에는 실제 게임 목록 이동을 함께 제공하며 사용자에게 내부 오류나 스택을 노출하지 않는다.
- 몰입형 게임 경로 판별을 라우트 표현 정책으로 단일화해 앱 셸과 오류 화면이 같은 기준을 사용한다. 새 테스트 파일은 추가하지 않고 기존 게임 페이지 테스트에 오류 격리 조건을 반영했으며, 전체 프런트 테스트 327개와 프로덕션 빌드를 통과했다.
