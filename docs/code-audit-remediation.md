# Code audit remediation

이 문서는 2026-08-16 전체 코드 감사에서 확인한 결함과 구조 개선 작업의 실행 순서를 고정한다. 각 항목은 독립된 커밋 하나로 완료하고, 검증이 끝난 뒤 상태와 커밋을 갱신한다.

| 순서 | 상태 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 완료 | 랭킹 결과의 클라이언트 신뢰 제거 | 서버가 발급한 시도만 완료할 수 있고, 서버가 게임 증명을 재검증해 산출한 결과만 랭킹에 노출된다. |
| 2 | 완료 | Supabase `SECURITY DEFINER` 실행 권한 최소화 | 의도한 RPC 외 함수의 `PUBLIC`/`anon` 실행 권한을 회수하고 Advisor 결과를 재확인한다. |
| 3 | 대기 | 취약 의존성 업데이트 | React Router와 전이 의존성 취약점을 제거하고 전체 검증을 통과한다. |
| 4 | 대기 | 게임 경로 변경 시 시작 게이트 우회 제거 | 현재 경로와 시작 승인을 동기적으로 결합해 새 게임의 선행 마운트를 막는다. |
| 5 | 대기 | 로컬 저장 키와 초기화 책임 통합 | 모든 게임 기록 키를 중앙 관리하고 초기화 누락을 제거한다. |
| 6 | 대기 | 게임 액션 피드백 CSS 중복 제거 | 기본·효과·배치 스타일의 소유권을 분리하고 import 순서 의존과 중복 keyframes를 없앤다. |
| 7 | 대기 | GameStage 전역/공용 셸 스타일 통합 | 무효화된 전역 선언을 제거하고 GameStage 스타일의 단일 소유권을 확립한다. |
| 8 | 대기 | 게임별 코드 분할 | 게임 컴포넌트를 지연 로딩해 초기 번들 경고와 불필요한 다운로드를 제거한다. |
| 9 | 대기 | 대형 게임·친구 모듈 책임 분리 | 상태 전이, 네트워크, 저장, 화면 렌더링 책임을 명시적 모듈로 분리한다. |
| 10 | 대기 | 앱/게임 Error Boundary 도입 | 화면 전체 백지화를 막고 복구 가능한 오류 화면을 제공한다. |
| 11 | 대기 | 공용 모달 포커스·스크롤 관리 정리 | 포커스 트랩, 배경 inert, 중첩 스크롤 잠금을 공용 관리자에서 처리한다. |
| 12 | 대기 | 정적 품질 게이트 도입 | ESLint, React Hooks, 접근성, Stylelint, 타입/정적 검사를 CI에 추가한다. |
| 13 | 대기 | Supabase 성능 Advisor 항목 정리 | 누락 FK 인덱스와 RLS initplan을 정리하고 미사용 인덱스를 사용 근거에 따라 결정한다. |

## 작업 원칙

- 증상을 가리는 선택자 추가나 임의 범위 제한 대신 원인이 된 책임과 신뢰 경계를 수정한다.
- 항목 사이의 변경을 섞지 않는다.
- 기존 테스트를 실행하고 필요한 경우 기존 테스트를 새 계약에 맞게 갱신하되, 별도 테스트 파일은 추가하지 않는다.
- 데이터베이스 변경은 마이그레이션으로 남기고 직접 테이블 쓰기보다 최소 권한 RPC를 사용한다.

## 1번 완료 기록

- 브라우저의 `game_results` 직접 INSERT 경로와 권한, RLS INSERT 정책을 제거했다.
- `begin_ranked_game`이 영구 계정에 일회성 시도를 발급하고, `complete_ranked_game`이 해당 사용자·시도·제출 ID를 잠금 상태에서 검증한다.
- 2048은 서버 시드로 보드를 재생해 점수를 산출하고, 메모리는 서버 시드와 라운드 입력 이력으로 상태·점수·최소 소요 시간을 재생한다.
- 스도쿠는 서버가 발급한 퍼즐과 제출 보드를 대조하고 서버 시각으로 소요 시간을 산출한다.
- 검증 시각이 있는 결과만 리더보드에 노출하며, 기존 클라이언트 신뢰 기록은 랭킹에서 제외한다. 기존 서버 전용 오목 기록은 유지한다.
- 별도 테스트 파일은 추가하지 않고 기존 프런트 테스트와 DB 계약 테스트를 새 흐름에 맞게 갱신했다.

## 2번 완료 기록

- PostgreSQL 함수의 기본 `PUBLIC EXECUTE`를 만든 함수마다 사후 회수하는 대신, `postgres` 소유자가 앞으로 `public` 스키마에 만드는 함수까지 기본 거부하도록 변경했다.
- 현재 `postgres` 소유 `public` 함수의 `PUBLIC`·`anon`·`authenticated` 실행 권한을 먼저 전부 회수한 뒤, 실제 클라이언트 RPC 26개와 RLS 평가용 함수 1개만 `authenticated`에 다시 허용했다.
- 로그인 전 공개가 제품 요구사항인 리더보드 RPC 하나만 `anon`에 허용했다.
- Auth 사용자 생성·활동 갱신·보존 정리 트리거와 플랫폼 `rls_auto_enable` 함수는 브라우저 역할이 직접 실행할 수 없게 했다.
- 적용 전 Security Advisor 기준 11개의 익명 `SECURITY DEFINER` 경고 중 10개가 제거 대상이며, 공개 리더보드 1개만 의도된 예외다. 인증 역할 경고는 명시적 RPC/RLS 허용 목록만 남긴다.
- 별도 테스트 파일 없이 기존 사전 출시 DB 테스트에 전역 함수 권한 행렬과 기본 권한 회귀 검사를 추가했다.
