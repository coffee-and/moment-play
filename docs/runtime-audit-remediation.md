# Runtime audit remediation

이 문서는 2026-08-19 전체 재검사에서 확인한 결함과 구조 개선 작업을 기록한다.
작업 브랜치는 `fix/runtime-audit-remediation`이며 기준 커밋은 `58fe481`이다.

## 작업 원칙

- 실제 원인을 소유하는 공용 계층에서 수정한다.
- 화면별 덮어쓰기, `!important`, 불필요한 전역 스타일과 임시 분기를 추가하지 않는다.
- 기능 스타일은 CSS Modules를 사용하고 공용 계약만 명시적으로 전역으로 유지한다.
- 전역 토큰과 기본값은 `src/shared/styles/foundation.css`가 소유한다.
- 상태 머신과 화면 책임이 결합된 게임만 분리한다. 파일 길이만 줄이기 위한 전달용 컴포넌트나 훅은 만들지 않는다.
- 각 변경은 독립 커밋으로 기록하고 관련 검사와 전체 품질 게이트를 통과시킨다.

## 작업 목록

1. [x] 로그아웃 실패 처리와 인증 상태 전환 계약 단일화

3. [x] 스타일 토큰과 구조 품질 게이트 강화
4. [x] 상태와 화면 책임이 결합된 대형 게임 컴포넌트 분리
5. [x] CI와 로컬 Node 런타임 계약 고정
6. [x] 전체 플레이 가능 게임 경로의 브라우저 회귀 검사 확장
7. [x] Omok `SECURITY DEFINER` 함수의 `search_path` 고정
8. [x] 현재 브랜치 전체 품질·테스트·빌드·브라우저·의존성·원격 CI 검증

Supabase의 유출 비밀번호 보호 기능은 Pro 플랜 기능이므로 사용자 요청에 따라 업그레이드 전까지 보류한다. 이 항목은 코드 우회나 대체 구현을 추가하지 않는다.

## 완료 기록

### 1. 인증 종료 계약

- 로그아웃 동작을 공용 훅으로 단일화하고 성공하기 전에 로컬 인증 화면 상태를 먼저 제거하지 않도록 했다.
- Supabase 로그아웃 실패를 호출 화면에서 동일한 사용자 오류로 노출하며 중복 요청을 막는다.
- 커밋: `7f10374`

### 2. 스타일 모듈 경계

- 인증, 설정, 친구, 퍼즐, 미니게임 페이지와 개별 게임 스타일을 CSS Modules로 이동했다.
- 전역으로 남은 기능 CSS는 게임 스테이지와 퍼즐 레이아웃의 명시적인 공용 계약 다섯 개뿐이다.
- 커밋: `06eace3`, `963ec64`, `3878b67`, `f206e4c`, `19cc985`

### 3. 스타일 품질 게이트

- `foundation.css`에 의미 기반 토큰을 모으고 인증·SET의 반복 원시 색상과 임의 pill 반지름을 제거했다.
- 기능 전역 CSS, foundation 밖의 원시 hex, 임의의 큰 반지름·z-index, CSS Module의 부수효과 import를 검사하는 구조 게이트를 `npm run quality`에 연결했다.
- 기존 Stylelint의 `!important`, 중복 선언, 상충 shorthand, 중복 선택자와 과도한 구체성 금지 계약을 유지한다.
- 커밋: `026c055`

### 4. 게임 컴포넌트 책임 분리

- Memory, 2048, Timing Tap, Block Blast는 상태 전이·수명주기를 전용 controller hook으로 이동하고 화면 컴포넌트는 렌더링 책임만 유지한다.
- Solitaire는 카드 표현과 기록 저장소를 독립 모듈로 분리해 도메인 표현과 브라우저 저장 책임을 제거했다.
- Omok은 이미 로컬 게임 상태, 온라인 룸 수명주기, 온라인 파생 상태와 메뉴·설정·로비·보드·대화상자 화면이 각각 분리되어 있다. 줄 수만 줄이는 거대한 전달용 wrapper는 새 결합을 만들므로 추가하지 않았다.
- 커밋: `695f946`, `1582343`, `b924f73`, `2362c02`, `ee1a60b`

### 5. 지원 런타임

- `.nvmrc`, `package.json` engines와 GitHub Actions가 동일한 Node 22 런타임을 사용하도록 고정했다.
- 커밋: `2920151`

### 6. 브라우저 범위

- 데이터 레지스트리의 플레이 가능 게임 14개 전부가 Pages base path에서 로드되고 시작 가능한지 검사한다.
- 구현 클래스나 내부 DOM 순서를 검증하지 않고 접근 가능한 사용자 계약과 실제 게임 진입을 검증한다.
- 커밋: `1703e54`

### 7. 데이터베이스 함수 보안

- Omok의 `SECURITY DEFINER` 함수 14개에 빈 `search_path`를 고정하고 함수 내부 객체 참조를 명시적으로 한정했다.
- pgTAP 회귀 검사를 추가했으며 격리된 DB CI에서 마이그레이션과 보안 검사를 통과했다.
- 커밋: `add35ff`

### 8. 전체 검증

- `npm run quality`의 ESLint, Stylelint, CSS custom property와 스타일 구조 검사가 모두 통과했다.
- Vitest 62개 파일 329개, 일반 프로덕션 빌드 314개 모듈, Pages 환경 Playwright 20개가 통과했다.
- `npm audit --audit-level=high` 결과 취약점은 0건이다.
- 기능 영역의 비모듈 CSS는 명시적인 공용 게임 계약 다섯 개뿐이며, CSS의 `!important`, foundation 밖 원시 hex와 임의의 큰 z-index가 없음을 재확인했다.
- 현재 브랜치 HEAD는 원격 GitHub Actions의 App·Database 작업으로 다시 검증한다.
